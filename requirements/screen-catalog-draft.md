## 利用者向け（LIFF）

### U-1. 招待ランディング `/liff/invite/:token`（**未ログイン閲覧可**）

**新規獲得の生命線。未登録の人が最初に見る唯一の画面。**

| 主要項目 | 備考 |
|---|---|
| 「〇〇さんから招待されました」 | **最上部**。人からの招待であることが広告との決定的な差。1対1の事実なので**人数が少なくても劣化しない** |
| もらえるもの（100pt）を登録前に明示 | 隠すと登録しない。ユーザー指示「もらえるものは先に提示する」 |
| 何をするのか（所要時間） | 「平均3分」のような**少人数でも劣化しない数字**を使う |
| 登録ボタン **1つだけ** | 選択肢を出さない |

**禁止（D-1）**: 参加人数・累計回答数・全体ゲージ・ランキング。少人数だと過疎の証明になる。

状態: 有効／期限切れ／上限到達／無効化済み／自己招待／既存会員が踏んだ／トークン不正

### U-2. キャンペーン専用ページ `/liff/campaign/:code`

**単一スクロール。**「進んでいる感じ」を分断しないため複数画面に割らない。

上から: ヒーロー（企画名・残り日数）→ **進捗ゲージ（1本に集約）** → ステージの階段（達成/現在/未達を縦に。**未達の報酬も最初から見せる**）→ **次の一手 CTA（1つだけ）** → 招待セクション（リンク＋LINEシェア）→ 招待した人の一覧 → これまでの記録 → 注意事項

状態: 未参加（階段はプレビュー）／参加中・次あり／参加中・次が今ない（**空にしない**）／ステージ達成直後／全達成／期間終了（CTA消す）／対象外（理由明示・無言404にしない）／未ログイン（R-8）

### U-3. ペア設問の回答 `/liff/pair/:pairId/answer`

既存 `partials/answer-ui.ejs` 流用。ペア専用の軽い設問（趣味・好み等）。**選択式のみ**（D-11）。
状態: 未回答／回答中／自分だけ完了（相手待ち）／両者完了→U-4へ／期限切れ／設問0件

### U-4. 答え合わせ結果 `/liff/pair/:pairId/result`

**②の体験の核。ここが面白くないとペアをやる意味がない。**

設計方針: 一致率を数字で出すだけでは弱い。
**「2人とも同じを選んだ」項目を先に見せ、違った項目を後に出す**——この順序が体験を作る。
`hallmark` で作り込む価値が最も高い画面。

**開示範囲（D-10 / D-11・規約制約）**:
- **相手の回答原文は一切見せない。** 返すのは**一致/不一致の判定のみ**（規約 v2.0 第10条4項(1)）
- 表示するのは「一致/不一致」と**自分自身の回答**、相手は**表示名のみ**
- **ペア設問は選択式のみ**（自由記述を入れない）＝構造的に原文開示が起きない状態にする
- 選択式なら「同じ選択肢を選んだか」だけで驚きは作れる。体験は損なわれない

状態: 両者完了（結果表示）／相手未回答（催促）／期限切れ／相手退会

### U-5. ステージ達成演出（画面ではなくオーバーレイ）

`partials/rank-celebration.ejs` 流用。`RankCelebration.maybePlay` と同型で発火。

## デザイン方針（構造として効く順）

1. **招待ランディングが最重要。** 未登録者が見る唯一の画面
2. **進捗は1本のゲージに集約。** 招待数・回答数・ステージを別々に見せるとどれも印象に残らない。Looop のゲージが効いていたのは1本だったから
3. **答え合わせは"結果"ではなく"驚き"として設計する**（一致→相違の順）。**原文を見せずとも成立する**——「2人とも『朝型』を選んだ」に相手のテキストは要らない（D-10）
4. **「協力するほど上がる」を数字で可視化。** 次のステージまであと何人／何回を常に出す。既存ランクの「次のランクまであと◯pt」と同じ思想
5. **規模は見せない**（D-1）。信頼は人数ではなく、招待者が実在すること・報酬が具体的であること・所要時間が明示されていることで作る
