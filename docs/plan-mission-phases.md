## Phase 3 — 隠し部屋・山分け・抽選 ✅ 実装済み（2026-09-04・migration 099 本番適用済み）

実装: [spec-mission-phase23-rooms-hidden.md](spec-mission-phase23-rooms-hidden.md) 参照。
開き方4種（N部屋クリア／日時／先着N／ランダム出現＝開く時刻だけ保存時に乱数確定）×
報酬3種（山分け＝締切後バッチ・一律＝読み時即付与・抽選＝等確率で締切後バッチ）。
下記の設計条件はすべて純関数＋DB CHECK で強制済み。

**元の方針（実装の根拠として保持）:**
**着手可（2026-09-04 決定）。ただし全報酬に1人あたり上限2,000ptを適用し、下記の設計条件を厳守する。**
弁護士確認は並行して行う（推奨・非ブロッカー）。根拠と論点: [requirements/legal-premium-act.md](../requirements/legal-premium-act.md)

| 要素 | 設計上の絶対条件 |
|---|---|
| 山分け | **1人あたり上限キャップ必須**（D-16）。仮に懸賞と評価されると上限2,000円 |
| ランダム出現 | **「いつ出るか」だけランダム。「何がもらえるか」は全員同じ**。開けてハズレは作らない |
| 抽選 | **「回答が多いほど当たりやすい」は採らない**（D-17・消費者庁Q19） |
| 先着 | 運用基準3に「先着順は懸賞に該当しない」と**明文**。最も安全 |
| 山分けの確定 | 参加者数が確定しないと1人あたりが決まらない → **締切後のバッチ**（Workers Cron）。画面に「結果は◯日にお知らせします」が要る |

**弁護士確認が要る論点（最重要3件）**:
1. アンケート報酬全体が運用基準5(3)「仕事の報酬」で通るか（1(1) に逆向きの記述があり専門家間でも解釈が割れる）
2. 抽選が「取引に付随しない」と言い切れるか（前提の「アンケート回答は取引か」が未確定）
3. 山分けが「偶然性を利用して価額を定める方法」に当たるか（**公式見解が存在しない**）

加えて**景表法以外**（資金決済法・賭博罪）の検討が未着手。

### 賭博罪の線引き（2026-09-04 確定・全企画に適用）

**「ポイントを消費して抽選に参加する」設計は絶対に入れない。**
賭博罪（刑法185条）の3要件——①財産上の利益を賭ける ②偶然で決まる ③得喪を争う——が
すべて揃う。Hibi のポイントはギフト交換できる＝経済的価値があるので「賭けた」が成立し、
くじを売る側として富くじ罪（187条）にも当たり得る。ソシャゲのガチャは当たりを換金できない
から成立しているが、Hibi にはその逃げ道がない。

| 形 | 判定 |
|---|---|
| 回答◯問で**無料**チケット → 抽選 | 賭けていない＝賭博でない。景表法の枠内で設計 |
| ポイントで**確定の物**と交換 | ただの交換（既存 eGift と同じ） |
| **ポイントを払って抽選** | ❌ 賭博構造。グレーではなく明確に不可 |

決定的な差は「**外れたとき何かを失うか**」。無料参加なら賭けが成立しない。
