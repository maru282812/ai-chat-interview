ミッション管理画面 — 設計案

既存 /admin/reward-campaigns を拡張する形。画面の並びと入力項目の確認用モック。

既存資産で足りるもの: reward_campaigns（032・器はある）／ projects.category（040・部屋の分類に流用）／ projects.max_respondents recruit_deadline（040/072・残り人数の分母）／ awardPoints の冪等キー／品質係数／当落のLINE通知（applications）。
新規で要るもの: ステージ定義／部屋定義／隠し部屋の開き方／参加者の進捗記録。

④ 隠し部屋の「開き方」

参加が10人なら 1人 2,000 pt（上限で頭打ち）／ 100人なら 1人 500 pt
※ 上限が無ければ10人で5,000pt/人となり、下記の理由で違反になる
⚠ 1人あたり上限は必須（景表法）。懸賞制限告示は「景品類の価額を定めること」も懸賞に含み、 運用基準1(4)「価額に差等があり判別できない方法」＝山分けと構造が同じ。 仮に懸賞と評価されると上限は2,000円（取引価額100円×20倍）。
⚠ ④ランダムは「いつ出るか」だけをランダムにする。「何がもらえるか」は全員同じにする。 開けてハズレがある設計＝相手方も価額も偶然で決まる＝懸賞になる。
⚠ 「回答が多いほど当たりやすい」は採らない（消費者庁Q19）。「参加できる」なら安全側。
③先着は運用基準3に「先着順は懸賞に該当しない」と明文があり最も安全。
詳細 → requirements/legal-premium-act.md

⑤ 案件指定型のとき — 残り人数の出し方

案件目標締切いまゲージ表示
カフェの朝の使い方50人2026-09-0812人 出す
通勤の実態調査——7人 出さない
ゲージは目標（max_respondents）と締切（recruit_deadline）が 実データで入っている案件だけ出す。未設定なら帯ごと出さない——分母が無いのに出すと捏造になる。 管理画面では設定されていない案件が一目で分かるようにして、運用側が埋められるようにする。
「12人が参加中」は出さないが「50人中12人・あと38人」は出す。差は分母の有無。

⑥ 進捗と付与の確認（不正の目視）

「要確認」の出し方が肝。招待9件に対し自分の回答が4件＝招待偏重は自作自演の典型。 同一端末（migration 086 で UA/IP が取れる）・短時間の連続登録も material になる。
⚠ 検出しても払った後の回収は現実的に不可能。だから 招待報酬は少額を即時／本命は相手が回答してからという順序で設計する。
取消は manual_adjustment で減算＝既存の台帳で表現できる。監査ログは必須。

⑦ 割り振りの全体像（データの流れ）

回答が入る → 品質判定（qualityScore）を通す → ミッションの対象か判定
　└ 横断型なら無条件にカウント／案件指定型ならその案件のみ
進捗を更新 → 段の条件（回答数 OR 招待数）を満たしたか判定
段を達成 → awardPoints（冪等キー campaign:{id}:{user}:stage{n}）
　└ 二重付与は既存の 23505 ハンドリングで防げる
最終段を達成 → 隠し部屋を解放 → 山分けは締切後に確定（上限キャップを適用）
　└ 参加者数が確定しないと1人あたりが決まらないため

判定はすべてサーバー権威。クライアントの進捗表示は信じない。
山分けの確定は締切後のバッチになる（既存 cronDispatchService／Workers Cron に乗る）。 ここだけ即時付与できない点は、画面上も「結果は◯日にお知らせします」と伝える必要がある。

⑧ テーマだけ差し替える

ミッションの中身（ステージ・条件・報酬・進捗）はそのままで、見た目だけ替える。 同じ企画を季節に合わせて着せ替える、反応が悪いテーマを差し替える、といった使い方。

変わるもの

見た目だけ 地の色・イラストの情景・見出しの言葉・CTAの色。
例: あき（紅葉）→ なつまつり（提灯と屋台）

変わらないもの

中身は全部そのまま ステージの条件・報酬額・部屋の割り当て・参加者の進捗・付与済みポイント・隠し部屋の開き方。
実装は theme_key を1列 UPDATE するだけ。 進捗も付与履歴も別テーブルなので、テーマを何度替えても参加者のデータは一切動かない。 だから公開中でも安全に差し替えられる。
⚠ 公開中の差し替えは「見た目が急に変わる」ことを意味する。 参加者から見ると昨日と別のページに見えるので、 ミッション名まで同時に変えると別の企画だと誤解される。名前は据え置くのが安全。
⚠ 変更履歴を残す。「反応が落ちたのはテーマを替えたせいか、報酬を変えたせいか」を 後から切り分けられないと、次の判断ができない。いつ・誰が・何から何へ替えたかを記録する。
⚠ 終了済みミッションのテーマは替えない（結果の振り返りと食い違う）。
